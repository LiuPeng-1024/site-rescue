# 第 5 章 · 找根因：马是怎么进来的

> 这一章是两次清理的本质区别。**复发不是马没删干净，是门没找到。**

## 思路：顺着马往回走

马已经在手里（第 3-4 章隔离的那些），问题是它怎么进来的。常见四条门：

1. **漏洞插件/主题**（最常见）
2. **弱密码被爆破**（wp-login / xmlrpc）
3. **面板/服务器凭据泄露**（宝塔、FTP、SSH、数据库）
4. **其他站交叉感染**（同一服务器上的兄弟站被黑传染）

## 操作一：访问日志刨时间线

```bash
# 拿插件目录名在日志里搜（换成你站里装过的插件名）
grep "wp-file-manager" /www/wwwlogs/你的域名.log | head -20

# 看可疑 POST（挂马/利用漏洞几乎都是 POST）
grep "POST" /www/wwwlogs/你的域名.log | grep -v "wp-login\|admin-ajax\|wp-cron" | head -20
```

真实案例：在日志里搜到一个早就不用的插件 `wp-file-manager` 有一堆直接 POST 请求——根因就是它。

## 操作二：漏洞插件识别

- 把已装插件逐个对一遍：还在维护吗？版本是最新吗？搜"插件名 + 漏洞"看有没有公开 CVE
- **"改名禁用"是自欺欺人**：把插件目录改名加 `.DISABLED`，只是后台看不见——Web 服务器照常提供访问，漏洞文件攻击者直接输 URL 就能打。真实案例的根因正是这个。**不用的插件，删，别改名**
- 用 nuclei + 公开模板扫版本漏洞（进阶，可选）

## 操作三：爆破痕迹

```bash
grep "wp-login.php" /www/wwwlogs/你的域名.log | awk '{print $1}' | sort | uniq -c | sort -rn | head
grep "xmlrpc.php" /www/wwwlogs/你的域名.log | awk '{print $1}' | sort | uniq -c | sort -rn | head
```

单 IP 请求数异常高 = 在被爆破（也说明为什么密码必须换、限速必须做）。

## 操作四：别忘了"不是挂马也能打死你"

还有一种"被黑"没有马：**扫描流量本身把小服务器打死**。真实案例：扫描器一分钟 60 个请求，php-fpm 子进程开满，2GB 内存耗尽，系统把 MySQL 杀了——网站报"数据库错误"，站长以为被入侵。查法：

```bash
dmesg -T | grep -i "killed process"    # 有没有进程被 OOM 杀
awk '{print substr($4,2,17)}' /www/wwwlogs/你的域名.log | sort | uniq -c | sort -rn | head   # 分钟级突刺
```
