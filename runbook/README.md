# 应急 Runbook（整理中）

宝塔 + WordPress 网站被黑应急排查修复的完整操作流程，按真实应急记录整理。

## 目录预告

1. **初检**：怎么确认被黑了（快照检查 / Googlebot 视角 / 常见症状清单）
2. **查马**：webshell 常见藏身位置、特征码扫描、可疑文件排查（含 goto 混淆壳识别）
3. **备份规矩**：动手前必须留的副本清单
4. **清理**：删除/隔离的正确姿势，易误判文件清单（如 189KB 静态 index.php 快照）
5. **找根因**：日志时间线、漏洞插件识别（"改名禁用"为什么是自欺欺人）
6. **加固**：wp-config 双 DISALLOW / REST API 收口（含 `?rest_route=` 坑）/ ?author 重定向 / 安全响应头 / 登录限速
7. **复查验证**：7 项检查清单 + 复发观察期

> 第 1-2 周优先整理，随免费帮清的真实案例持续校准补充。
> 等不及的可以先看[复盘文章](../articles/01-网站被黑挂马两次-应急全过程.md)，核心步骤都在里面。
