# sr-scan — 宝塔 + WordPress 被黑排查扫描器(免费快扫)

一句话:在服务器上跑一行命令,告诉你网站有没有明显的被黑痕迹(webshell、赌博跳转、危险残留文件)。**只读,不改你网站的任何文件。**

## 三步开跑(宝塔用户)

**第 1 步**:登录宝塔面板 → 左侧「终端」(或用自己的 SSH 工具连上服务器)。

**第 2 步**:粘贴下面这行命令,回车 —— 把扫描器下载到服务器当前目录:

```bash
curl -o sr-scan.py https://raw.githubusercontent.com/LiuPeng-1024/site-rescue/main/scan/sr-scan.py
```

如果提示没有 curl,用 wget(效果一样):

```bash
wget -O sr-scan.py https://raw.githubusercontent.com/LiuPeng-1024/site-rescue/main/scan/sr-scan.py
```

如果下载超时（部分服务器访问 GitHub 不稳）：在你自己电脑上打开这个链接，把文件另存为 sr-scan.py，然后用宝塔面板的「文件」管理器上传到服务器任一目录（比如 /root 或 /tmp），再在终端里 `cd` 过去执行第 3 步。

**第 3 步**:再粘贴这行,回车 —— 把路径换成你自己的网站目录(宝塔默认在 `/www/wwwroot/你的域名`):

```bash
python3 sr-scan.py /www/wwwroot/mysite.com --url https://mysite.com
```

几个说明:

- 不确定有没有 python3?先敲 `python3 --version`,显示版本号就行(3.6 以上都可以)。没有的话试试 `python`;宝塔面板的服务器一般都自带 Python。
- `--url` 可填可不填:填了会多做网络检查(REST 用户枚举、伪装跳转初检、wp-cli 核心校验);不填就只做本地文件检查,一样能跑。
- 只看最近 7 天被动过的文件:加 `--days 7`(默认 14 天)。
- 想把报告存成文件慢慢看:加 `--json report.json`,之后可用宝塔文件管理器把 report.json 下载到本地。

## 看懂报告

报告分四段,重点是第一段:

- **【高危】** —— 基本可以确定是马或被黑特征:uploads 目录里出现 PHP、`eval($_POST)` 一句话木马、goto 混淆文件、给搜索引擎看赌博页面等。**有几条就要处理几条**,每条都带文件路径和行号。
- **【可疑】** —— 不一定是坏事,但需要你确认:最近被修改过的 PHP(是不是你自己改的?)、debug.log / .sql / 压缩包残留、.git 目录暴露。
- **【提醒】** —— 加固建议和基本信息:WordPress 版本、已安装插件清单、wp-config.php 缺了哪些防护开关。
- **【通过项】** —— 查过且没发现问题的检查,让你知道哪些面是覆盖到的。

程序退出码:发现任一高危 = 1,否则 = 0(写脚本批量巡检时可以用)。

## 发现高危后,第一步做什么

**先备份,别慌删。**

1. 宝塔面板 →「网站」→ 备份站点;「数据库」→ 备份。有备无患,后面怎么操作都不怕。
2. 把报告列出的高危文件**隔离,而不是直接删除**:在宝塔文件管理器里把它们移到网站目录之外(比如 `/www/backup/quarantine-今天日期/`),或先打包下载再删原文件。留着证据,才能查清"是怎么进来的"。
3. 改密码:宝塔后台、WordPress 后台、数据库、FTP / SSH,全部换掉。
4. 更新:WordPress 核心、全部插件和主题升到最新版;不用的插件直接卸载。
5. 按报告【提醒】段,给 wp-config.php 加上 `define('DISALLOW_FILE_EDIT', true);`。
6. 完整处置流程见仓库 runbook:[../runbook](../runbook) · https://github.com/LiuPeng-1024/site-rescue

## 它会不会动我的网站?

不会。扫描器**绝对只读**:不修改、不删除、不移动你网站的任何文件,也不往网站目录里写东西。唯一会写的文件,是你自己用 `--json 路径` 显式指定的那份报告。整个工具就一个 Python 文件、只用标准库,欢迎自己过目源码。

## 会不会误报(把正常文件当木马)?

可能性不大,但这几类要知道:

- **随机文件名检查**:极少数合法插件可能用了无意义命名的文件。命中后打开文件看一眼,内容正常就不用管。
- **preg_replace /e 检查**:这个语法 PHP 5.5 起就废除了,正规插件早已不用,命中基本是真问题;但理论上可能误伤写法怪异的古老代码。
- **create_function / 命令执行函数 / 超长单行检查**:非常老的正版插件(PHP 5 时代)、个别自带运维功能的备份插件、把大段数据写进 PHP 的插件,理论上可能撞上这几条。命中后打开文件看一眼:能看出正常业务逻辑的,加入人工白名单即可。
- **危险残留文件**:debug.log、.sql、.zip 如果是你自己备份留下的,不奇怪 —— 但用完记得删,放在网站目录里谁都能下载。
- **最近修改文件**:你刚更新过插件/主题,它们就会上榜。这一段是给你核对用的,不是定罪。

另外,本工具是**特征码初筛,不等于深度取证**:报了高危,人工确认后再处置;没报高危,也不代表 100% 干净 —— 网站仍有异常(排名掉、跳转、收录赌博词)时,请人工排查或到仓库找我们。

## 常见问题

- **报 `python3: command not found`**:换 `python` 试试;都没有的话,在宝塔「软件商店」装 Python 项目管理器,或用系统包管理器装 python3。
- **网络检查失败/超时**:服务器可能限制了外发请求,去掉 `--url` 只跑本地检查即可。
- **想查得更深**(WordPress 核心文件逐字节比对官方):在服务器上装好 wp-cli 后,带 `--url` 运行时本工具会自动调用 `wp core verify-checksums`;你也可以自己手动跑这条命令。
- **Windows 服务器**:本工具主要为宝塔 Linux 设计,Windows 上装了 Python 3 也能跑。
